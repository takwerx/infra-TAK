Database Maintenance (CoT) ▾

The CoT database can grow large. Data retention deletes old rows, but PostgreSQL does not free disk until you run VACUUM. Guard Dog runs smart auto-VACUUM daily at 3am (when dead tuples exceed 1M).

Database size
-
Estimated rows
-
Dead tuples
-

Size: green < 25 GB · yellow 25–40 GB · red > 40 GB. Dead tuples > 1M triggers auto-VACUUM.

VACUUM ANALYZE — marks deleted space for reuse. Database stops growing but file size unchanged. Safe while running.
VACUUM FULL — physically shrinks files on disk. Locks tables, stop TAK Server first. (caution)
REINDEX — rebuilds indexes for faster queries. Safe while running but may be slow on large databases.

Rotate Intermediate CA ▾

Create a new Intermediate CA signed by your Root CA. The server TLS cert is not replaced, so existing ATAK clients keep connecting. The old CA stays in the truststore; new client certs are signed by the new CA. When everyone has re-enrolled, use Revoke Old CA.

Revoke Old CA

Final step: create new server cert (signed by new CA), remove the old CA from the truststore, restart. After this, only clients who re-enrolled (e.g. new CloudTAK QR) can connect. Do this when everyone has re-enrolled.

Rotate Root CA ▾

Full PKI rebuild. Creates a new Root CA, new Intermediate CA, new server cert, and regenerates all client certificates. All existing connections will be disconnected. Users must re-enroll via TAK Portal QR code. Schedule a maintenance window before proceeding.

Federation ▾

Server-to-server federation lets two TAK Servers share data directly over V2 TLS (port 9001 by default). Exchange CA certificates, then one side creates an outgoing connection to the other. The receiving side needs the federation port open in the firewall.
