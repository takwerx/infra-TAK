Getting started

Before you deploy

  • Caddy and Authentik must already be deployed. ATLAS publishes its console as a Caddy vhost behind Authentik sign-in, and registers itself as an Authentik application. ⚠️ Without Authentik the deploy still succeeds but the console vhost is not published, and the log says so.
  • A domain pointed at this box. The console lands on atlas.<your-domain>.
  • One Android tablet you can factory reset. Device Owner can only be established during the out-of-box wizard — there is no way to convert a set-up device.

1. Deploy

Press Deploy ATLAS. It clones the pinned release, builds the image, generates a device certificate authority, opens :8449 for devices, registers the Authentik application and restricts it to administrators. Seven steps, 5–10 minutes on the first run.

2. Open the console

https://atlas.<your-domain>, signing in through Authentik. The Android agent and launcher are already loaded — they ship with the release and are installed into the app library on first start, so there is nothing to upload.

3. Enrol one device

  • On the Enroll page, create an enrollment token.
  • Fill in the Wi-Fi the tablet should use while provisioning, then Generate enrollment QR.
  • On the factory-reset tablet, tap the first setup screen six times in the same spot to open the QR scanner, and scan it.
  • The tablet joins Wi-Fi, installs the agent as Device Owner, and appears on Manage within a few seconds.

⚠️ The QR expires after 15 minutes by default — it is a live credential, and a photograph of it is too. There is a permanent option for a provisioning bench, with the trade explained on the page.

4. Then use the guides inside ATLAS

The Guides section of the console covers policies, app deployment, kiosk mode, content and device identification. They live with the release, so they describe the version you are actually running.

⚠️ One security step afterwards. A new install keeps the certificate authority's root key on this server, where anyone who reaches the box can take it and mint a device identity for ever. Once ATLAS is running, the Certificate authority card on this page walks through moving it somewhere safer. Devices are unaffected and nothing needs to be touched on any tablet.

Renew the issuing certificate

ATLAS signs device certificates with an issuing certificate. When it expires, every device stops authenticating. Renewing it needs the root key, which is deliberately not kept on this server.

Devices roll onto the new certificate by themselves — nothing needs to be done to any tablet.

Choose nothing if the root key is still on this server — that is the usual case, and the console will use the key it already has. A file you choose is written for the length of one command and removed immediately afterwards, whether the command succeeds or fails.

Remove deployment

⚠️ This destroys that deployment's device CA and database. Every tablet enrolled against it is signed by that CA. Once it is gone they cannot be re-adopted — each needs a factory reset, in person. Other deployments on this box are untouched.

Uninstall ATLAS

Removes ATLAS completely: every deployment on this box, with its containers, images, database volume, reserved store, install directory, Caddy vhosts and its own Authentik application. Installing again rebuilds all of it from scratch.

⚠️ This destroys every device CA and every database. Each enrolled tablet's identity is signed by its own deployment's CA. Once those are gone the tablets cannot be re-adopted — each needs a factory reset, in person. There is no undo and no backup taken.

To remove a single deployment and leave the others running, use Remove on its row instead.
